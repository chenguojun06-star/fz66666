一、结论先说

框架已就绪，但只接了约 1% 的界面。当年搭好的多语言地基是完好的、可用的，不需要推倒重来；真正缺的是「把 1.3 万条中文文案搬进语言包」这件体力活，以及几个前置决策。

关键结论：后端不用改。状态值和字典值在数据库里本来就是英文 code（not_started / WOMAN / BLACK），中文只是前端的展示映射。这意味着多语言是纯前端工程，风险比预想的小得多。

工期结论：全量上线约需 172 人天（≈8 人月）。但不必等全部做完 —— 分 4 个里程碑交付，最快 2–3 周内部可试用，约 1.5–2 个月工厂端就能真正用起来。

六、必须提前决策的 4 件事

1. 打印模板印什么语言？
标签、洗水唛、U 码、购销合同都要印刷。工人看不懂英文标签 = 整个多语言白做。这是项目红线文件（打印样式不可擅动），必须业务先定：是随界面语言走，还是固定印中文/英文。
2. 高棉语找谁翻？
英、越可 AI 初翻 + 业务校对；高棉语（柬埔寨）机器翻译质量差且缺乏服装行业语料，建议直接外包给专业翻译，否则宁可不做这一种语言。
3. 字典项要不要一起翻译？
字典（颜色、尺码、季节、款式类型）由业务自己在「字典管理」里维护。若翻译，需给 t_dict 加多语言列或建立 code→译文映射，会改变业务人员的维护习惯。
4. h5-web 是否纳入？
h5-web 完全未接入，且它是小程序源码的镜像宿主。若不对外投放，可暂不纳入，避免工作量翻倍。

十、三大工期风险

风险 1 · 打印模板（47 个文件）—— 最容易失控
涉及标签、洗水唛、裁床单、工资条、工厂对账单、吊牌证书、报价单、生产制单等。这些文件是项目红线（打印样式不可擅动），且必须真机打印才能验证。更关键的是：业务方必须先决定「标签印哪种语言」——这个决策一旦延后，整块工作无法启动。
风险 2 · 文本膨胀撑破布局
英文比中文长 30–50%，越南语带声调符号更宽更高，高棉语字符结构复杂。所有按钮、标签、表格列宽、卡片高度都可能溢出。这不是改文案，是重新做一遍视觉走查，覆盖全部 1,370 个 PC 页面 + 72 个小程序页面。最容易被低估，也最容易导致「翻译完了但界面不能看」。
风险 3 · 语言包体积撞上小程序主包上限
13,726 个 key × 4 种语言，未压缩约 2 MB+；而微信小程序主包上限为 2 MB。语言包一旦全量塞进主包，其他功能将被挤爆。必须提前设计按需加载或分包策略（工作包 E），否则后期返工代价极大。

十一、其他提示

  • 小程序改动需发版才生效（CI 不构建小程序），语言包更新同样要走上传→审核→发布流程。
  • 三份副本必须同步：miniprogram/ 是唯一源，改完需同步 h5-web/source-miniapp/ 与 h5-web/public/source-miniapp/，仓库有 pre-push 校验会拦截不一致。
  • 提交纪律：本工作区多会话并发，795+ 文件改造必须按模块分批 git commit -o -- <path>，禁止 git add -A。
  • 语言包增长可控：语言包从当前 118 行增至约 1.4 万 key 后，前端产物体积约增加数百 KB（gzip 后更小），需留意小程序主包体积上限（2MB）。建议小程序语言包按需分包或只保留所需命名空间。
