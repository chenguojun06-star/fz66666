## 二、激活混合检索（named-vectors）的真实代价

### 核心事实：换集合名 ≠ 只加一路检索

激活路径要求**换一个新集合名**，而新集合是空的。重灌端点（`SparseVectorBackfillRunner`）**只覆盖两类数据**：
1. 全库表结构 schema
2. SOP 程序记忆

**留在旧集合、新集合里没有的**（这几处共用同一个 `collectionName`，已逐行确认）：

| 数据 | 写入点 | 切集合后 |
|---|---|---|
| 记忆向量 `mem_*` | `IntelligenceMemoryOrchestrator:93` | ❌ 全部取不到 |
| 知识库向量 `kb_*` | `KnowledgeSearchTool:296` | ❌ 全部取不到 |
| **语义缓存** | `SemanticCacheService:312` | ❌ **全 miss** |
| Crew 建议 `crew_adv_*` | `ProductionAgenticCrewOrchestrator:252` | ❌ 取不到 |
| 自进化洞察 `evolution_*` | `AiSelfEvolutionService:38` | ❌ 取不到 |
| 归档记忆 | `MemoryArchiveJob:164/200`、`MemoryArchiveService:319` | ❌ 取不到 |
| 款式图片向量 | 独立集合 `style_images` | ✅ 不受影响 |

**语义缓存全 miss 是最大的隐性成本**：缓存失效后每个问题都要完整走一遍 LLM，
在"配额刚从 20 万提到 200 万"的背景下，这会让成本曲线再上一个台阶。

### 风险分级

| 维度 | 等级 | 说明 |
|---|---|---|
| 数据安全 | 🟢 低 | 旧集合全程只读、不删不改，把集合名改回去即完整回退 |
| 可用性 | 🟡 中 | 重启 → 重灌完成之间存在空窗期，RAG 上下文取不到东西（不是报错，是空结果） |
| 成本 | 🟡 中 | 重灌 ≈ 100~300 次 embedding 调用 + 语义缓存失效后的 LLM 回源 |
| **效果** | 🔴 **未知** | **没有基线。开了也不知道是变好还是变坏** —— 这才是最大的问题 |

顺便纠正一个可能的误解：17:40 那次"小云完全答不出"是 `search()` **返回 400 报错**（异常），
跟"新集合空 → 检索无结果"不是一回事。空结果是降级，400 是故障。

## 三、有一条代价小得多的替代路径（待验证）

**不换集合名，给现有 `fashion_memory` 直接追加 sparse 配置。**

依据：Qdrant 官方文档明确写了 "Named vectors can be added to or removed from an existing collection without having to recreate the collection"，
且 `PATCH /collections/{name}` 支持更新 `sparse_vectors`。也就是说：

```
PATCH /collections/fashion_memory
{ "sparse_vectors": { "text-sparse": {} } }
```

然后代码只需要改一处 —— `QdrantService.detectVectorMode()` 里改成：

```java
// 现在：named=false 时 sparse 一律不可写
sparseWriteEnabled = named && params.path("sparse_vectors").has(SPARSE_VECTOR_NAME);
// 改成：只要有 sparse_vectors 声明就可写（未命名 dense + 命名 sparse 是 Qdrant 支持的组合）
sparseWriteEnabled = params.path("sparse_vectors").has(SPARSE_VECTOR_NAME);
```

**好处**：记忆、知识库、语义缓存全部原地保留，切换代价从"丢 5 类数据"降到"只补 sparse 字段"。
**前提**：需先确认线上 Qdrant 版本支持该更新（≥1.4），且未命名 dense + 命名 sparse 能共存 —— 建议在 staging 或本地先试一次。

## 五、一句话回答"激活有什么风险"

**数据不会丢（可完整回退），但会丢"已有的检索资产"——记忆、知识库、语义缓存会全部留在旧集合。**
真正让人不安的不是风险本身，而是**现在没有任何基线，开了之后你无法判断它到底有没有变好**。
所以：先花 1 小时跑评测集，再决定动不动。
