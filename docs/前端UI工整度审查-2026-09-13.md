# 前端 UI 工整度审查（2026-09-13 23:10）

> 目标：找出"不工整 / 花哨"的点，量化到文件与次数。
> 方法：全量扫描 `frontend/src`（1026 个 tsx + 91 个 css，共 **25491 行 CSS**），统计装饰属性、间距/字号/圆角分布、token 使用率、样式债。

---

## 一、结论先行

**三句话：**
1. **不是没规范，是规范没守住。** `design-system.css` 定义了 **502 个 token**（间距 8 档、圆角 6 档、字号 12 档），全站 `var()` 调用 3263 次 —— 体系是建起来了。但同时有 **511 处硬编码 hex**、**649 处野值间距**、**1731 处内联硬编码 px**。
2. **"花哨"高度集中在 8 个文件**，不是全站性的。其中 `IntelligenceCenter/styles.css` 的文件头注释自己写着"深空黑底 + 霓虹青/绿/紫 + 动态脉冲 + 扫描线"—— 这就是你要去掉的东西，而且是**明写在设计意图里**的。
3. **真正的重活是 7946 处内联样式**，占了大头，且只能渐进清理，不能一次性重构（985 个 `!important` 说明历史上覆盖关系已经很乱，全量改动风险高）。

## 四、问题二：规范未守住（"不工整"的根因）

### 4.1 间距：649 处用了 token 之外的野值

已有 8 档 spacing token：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`

实际使用频次：

| 值 | 次数 | 是否在 token 内 |
|---|---|---|
| 8px | 420 | ✅ sm |
| 12px | 332 | ✅ base |
| **6px** | **244** | ❌ **野值** |
| 4px | 243 | ✅ xs |
| **10px** | **229** | ❌ **野值** |
| 16px | 141 | ✅ md |
| 2px | 124 | ⚠️ 多为边框补偿 |
| 20px | 77 | ✅ lg |
| **14px** | **71** | ❌ **野值** |
| **3 / 5 / 7 / 9px** | **105** | ❌ **野值** |

**野值合计 649 处。** 这就是"看着不够整齐"的直接来源——同样的内边距，A 处 12px、B 处 10px、C 处 6px，肉眼能感觉到参差。

### 4.2 圆角：7 种并存，token 几乎没用

```
8px ×79    6px ×75    4px ×66    12px ×42    10px ×31    2px ×25    3px ×16
var(--radius-sm) ×9   ← token 调用只有 9 次
```

定义了 6 档 radius token，实际调用 9 次，其余 330+ 处直接写数字。

### 4.3 字号：13 个档位

```
14×361  13×130  12×122  11×76  16×39  15×31  18×19  9×9  10×6  8×5  20×5  28×3  24×2  7×1  36×1
```

而且 token 本身就有冗余：`--font-size-title:16` 与 `--font-size-lg:15`、`--font-size-subtitle:15` 语义重叠；`--font-size-base:14` 与 `--font-size-md:14` **完全重复**。

## 五、问题三：样式债（决定"能不能改得动"）

| 项 | 数 | 含义 |
|---|---|---|
| `!important` | **985** | 覆盖关系已成网，改一个全局类可能牵连多处 |
| 内联 style | **7946** | 无法被主题/暗色模式覆盖，也无法批量收敛 |
| 硬编码 hex | 511 | 换主题时逐个漏改 |
| z-index 硬编码 | 35 | 弹窗层级冲突隐患 |

**这决定了改动策略：不能全量重构，只能"分区治理 + 新增严守"。**

## 六、优化清单（按性价比排序）

### P0 — 见效最快，风险最低（约 0.5 天）

1. **删除 `IntelligenceCenter/styles.css` 的 7 个装饰动画**
   去掉 pulse / blink / neon / scan / border-breath，静态化。单文件、无外部依赖、视觉变化最明显。
   **闪烁 `blink-alert` 优先删**（可访问性）。

2. **收敛圆角为 3 档**：`4px`（按钮/输入）· `8px`（卡片/面板）· `999px`（药丸标签）。
   全站替换 6/10/12/2/3px → 就近档位，约 330 处，可脚本化批量替换 + 抽样目检。

3. **收敛字号为 5 档**：`12 / 13 / 14 / 16 / 20`。
   9/10/11/15/18/24/28/36 归到就近档位，同步清理 token 里的重复项（base=md、subtitle=lg）。

### P1 — 规范收口（约 2-3 天）

4. **间距迁移到 8pt 网格**：6px→4 或 8、10px→8 或 12、14px→12 或 16，共 649 处。
   建议按模块分批（dashboard / basic / production / warehouse …），每批跑一遍目检。

5. **511 处硬编码 hex 收进 token**。先把出现 ≥5 次的色值提炼成 token，长尾逐个替换。

6. **装饰阴影收敛为 2 级**：卡片级（弱）、浮层级（强），删除所有彩色发光阴影。
   重点：`IntelligenceCenter`(45)、`Layout`(16)、`StyleInfo`(16)、`Dashboard`(12)、`AgentActivityPanel`(14)。

7. **backdrop-filter 清理**：31+12+10 处集中在 3 个文件，毛玻璃在 1 核 2G 的机器上还费性能。

### P2 — 长期治理（持续）

8. **内联样式 7946 处渐进清理**：存量不动，**新增代码禁止 `style={{}}` 写布局与尺寸**，
   只保留真正动态的（如拖拽位置、进度百分比）。可在 CI 加 ESLint 规则拦截。

9. **z-index 建立层级常量**：`--z-dropdown:1000 / --z-modal:1050 / --z-toast:1100`，替换 35 处硬编码。

10. **985 个 `!important` 逐个审**：大部分是为了压第三方组件（antd），可集中到 1-2 个 override 文件统一处理。

## 七、改动前必须知道的风险

1. **985 个 `!important` + 5 个主题文件并存**（`global.css` 72KB / `design-system.css` 40KB / `dark-theme-global.css` 31KB / `lightSense.css` / `animations.css`）
   → 改全局样式**极易牵一发动全身**。务必每次只改一个维度（例如这一轮只动圆角），改完跑一遍主要页面目检。

2. **7946 处内联样式无法通过改 CSS 覆盖**，所以"改了 token 但页面没变"的情况会很多。
   这类页面必须单独改 tsx，工作量主要在这里。

3. **建议先做 P0-1（一个文件）作为试点**，确认视觉方向和你的预期一致，再推开。
   否则可能改完一轮才发现方向不对，白做。

## 八、需要你拍板

1. **装饰删到什么程度？** 我建议：除了 loading / 状态切换 / 展开收起这类**功能性动效**，其余全部去掉。
   但"智能运营驾驶舱"这类页面当初可能就是为了"科技感"做的 —— 是彻底扁平化，还是保留少量氛围？
2. **先从哪个页面开始？** 建议 `IntelligenceCenter`（最花哨且独立）。
   或者反过来，先做**首页 Dashboard**（影响面大但只有 501 行，见效快）。
3. **要不要立一条 CI 规则**拦截新增的内联布局样式？不立的话，P2 清完还会重新长出来。
